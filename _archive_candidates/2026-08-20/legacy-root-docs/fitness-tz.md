# Техническое задание: Фитнес-приложение (Telegram Mini App)

**Версия документа:** 1.0 (Production-Ready)

**Цель:** Предоставить исчерпывающую инструкцию для разработки универсального фитнес-приложения в среде Telegram Mini Apps с поддержкой оффлайн-режима и гибридного AI-тренера.

**Статус монетизации:** MVP полностью бесплатен, но архитектура БД и бэкенда должна поддерживать будущее внедрение Telegram Stars.

---

## 1. Обзор продукта и цели MVP

### Целевая аудитория

Универсальная (от новичков, желающих начать заниматься дома, до опытных атлетов, ведущих дневник тренировок).

### Ключевые модули MVP

- Каталог упражнений (видео/анимация, техника, типичные ошибки)
- Готовые программы тренировок и конструктор своих
- Таймер тренировки (интервалы, отдых, трекер подходов/повторений)
- Трекер прогресса (графики, календарь, streak, достижения)
- Трекер питания (дневник приёмов пищи + автоподсчёт КБЖУ из локальной/внешней базы)
- Цели и привычки (ежедневные чекины)
- Гибкие напоминания о тренировках через Telegram Bot
- AI-тренер: чат-помощник, умный подбор программы по анкете, адаптация расписания при пропусках, анализ прогресса с рекомендациями

### Критические нефункциональные требования

- **Offline-First:** Приложение должно позволять начать и завершить тренировку без интернета (данные кэшируются и синхронизируются при появлении сети)
- **Нативность:** Строгое соблюдение гайдлайнов Telegram (системные цвета, HapticFeedback, MainButton)

## 2. Архитектура системы

```
[Клиент: Telegram Mini App]
  ├── React + Vite + TypeScript + Tailwind CSS
  ├── Стейт: Zustand | Данные: TanStack Query
  ├── Оффлайн: Dexie.js (IndexedDB) + Service Worker
  └── Telegram SDK: @telegram-apps/sdk (initData, Haptics, UI)
          │
          │ (HTTPS, JWT + валидация initData)
          ▼
[Бэкенд: Python + FastAPI]
  ├── Маршрутизация и валидация (Pydantic)
  ├── Гибридный AI-движок (Rule-based логика + LLM API + RAG)
  ├── Rate Limiter (Redis)
  └── Фоновые задачи (Celery / Arq для напоминаний и синхронизации)
          │
          ├─▶ [База данных: PostgreSQL (Supabase)]
          │     ├── Основные данные (users, workouts, exercises)
          │     └── pgvector (для RAG AI-тренера)
          │
          ├─▶ [Хранилище медиа: Cloudflare R2 (S3-compatible)]
          │     └── Видео и анимации упражнений
          │
          └─▶ [Админ-панель: Refine.dev / Strapi]
                └── Управление контентом, пользователями, промптами
```

## 5. Сценарии использования и экраны Mini App

### Онбординг (первый запуск)

- Запрос `initData` и создание/обновление пользователя
- Пошаговая форма: цель (похудение/набор/поддержание), уровень, доступное оборудование, ограничения по здоровью
- Экран загрузки: «AI составляет вашу первую программу...» (вызов LLM)

### Главный экран (Dashboard)

- Приветствие + статус на сегодня («Сегодня: День груди. Осталось 45 мин»)
- Крупная кнопка MainButton или карточка «Начать тренировку»
- Мини-карточки: Streak (дней подряд), калории сегодня
- Блок «Совет от AI-тренера» (динамический, на основе последних логов)

### Экран активной тренировки

- Название упражнения, видео/гифка, текст техники
- Трекер подходов: поля «Вес», «Повторения», чекбокс «Выполнено»
- Встроенный таймер отдыха с HapticFeedback (вибрация при окончании)
- Кнопка «Завершить тренировку»

### Экран завершения

- Сводка: время, общий объём (тоннаж)
- Поле для заметок, слайдер оценки сложности (RPE 1–10)
- Мгновенная AI-рекомендация: «Отличная работа! Завтра день отдыха, рекомендую...»

### Трекер питания

- Дневной вид: Завтрак, Обед, Ужин, Перекус
- Поиск продукта по названию (автокомплит из БД `nutrition_products`)
- Ввод граммовки → автоматический пересчёт КБЖУ и обновление дневной полосы прогресса

### AI-Чат

- Интерфейс, похожий на Telegram
- Быстрые промпты-кнопки: «Почему болят колени?», «Замени жим лёжа», «Проанализируй мой прогресс за месяц»

## 6. Спецификация AI-агента (гибридный подход)

Для контроля затрат и скорости используется двухуровневая система.

### Уровень 1: Rule-Based (Python)

- **Сдвиг расписания:** если пользователь пропустил тренировку, скрипт просто сдвигает все `scheduled_date` в таблице `workouts` на 1 день вперёд
- **Расчёт КБЖУ:** простая математика на бэкенде, без вызова LLM

### Уровень 2: LLM + RAG (Groq API)

- **RAG (Retrieval-Augmented Generation):** при запросе пользователя векторизуем запрос, ищем в pgvector топ-3 наиболее релевантных упражнения или статьи из базы знаний, передаём их в контекст LLM
- **Системный промпт (пример):**
  > Ты — профессиональный, сертифицированный фитнес-тренер и нутрициолог. Твой тон: поддерживающий, мотивирующий, но научно обоснованный. Ты работаешь с пользователем {user_name}, его цель: {goal}, текущий вес: {weight}. Никогда не давай медицинских диагнозов. При рекомендациях упражнений ссылайся только на данные из предоставленного контекста (RAG). Формат ответа: краткий, с использованием эмодзи и списков.
- **Анализ прогресса:** раз в неделю (или по запросу) агент получает агрегированные данные из `workout_sets` и `nutrition_logs` за последние 14 дней и генерирует текстовый отчёт с одной конкретной рекомендацией по коррекции

## 7. Интеграции

### Telegram Bot API

- Отправка напоминаний: `sendMessage` с `reply_markup` (Inline Keyboard с deep link на открытие Mini App: `https://t.me/your_bot/app?startapp=workout_123`)
- Команда `/start`: генерация ссылки на Mini App

### Telegram Web App API

- `window.Telegram.WebApp.initData` (для авторизации)
- `window.Telegram.WebApp.HapticFeedback.impactOccurred('light')` (при завершении подхода или таймера)
- `window.Telegram.WebApp.MainButton` (для основных действий)
- `window.Telegram.WebApp.CloudStorage` (опционально, для хранения настроек темы, но приоритет — своя БД)

### Внешние API

- OpenFoodFacts (только для первоначального парсинга/обогащения базы, не для real-time запросов в MVP)

## 8. Безопасность и валидация

### Авторизация

1. Фронтенд передаёт `initData` (строку) на бэкенд при первом запросе
2. Бэкенд обязан проверить HMAC-SHA256 подпись строки `initData`, используя токен бота из BotFather (использовать официальную библиотеку или проверенный алгоритм валидации)
3. При успехе бэкенд генерирует собственный JWT-токен сессии (срок жизни 30 дней), который фронтенд сохраняет в `localStorage` и использует в заголовке `Authorization: Bearer <token>`

### Валидация данных

- Строгая валидация всех входящих JSON через Pydantic на бэкенде и Zod на фронтенде

### CORS

- Настроен строго на домен `https://web.telegram.org` и кастомный домен приложения

## 13. Rate limiting для LLM

Чтобы избежать неконтролируемых расходов на токены и злоупотреблений:

| Мера | Описание |
|------|----------|
| Лимит на пользователя | Максимум 15 AI-запросов (чат/анализ) в сутки на одного `user_id` |
| Реализация | Redis-based Token Bucket на бэкенде (FastAPI + slowapi или кастомный middleware) |
| Кэширование | Хэширование запроса пользователя. Если идентичный запрос уже обрабатывался за последние 24 часа, отдавать сохранённый ответ из БД, не вызывая LLM |
| Fallback | При превышении лимита или ошибке LLM возвращать дружелюбное сообщение: «Лимит советов на сегодня исчерпан, попробуйте завтра! А пока вот базовая рекомендация...» |

## 15. Источник данных о продуктах питания (инструкция по импорту)

Для обеспечения работы трекера питания без постоянных внешних запросов необходимо создать локальную базу в `nutrition_products`.

### Шаг 1: Получение данных

**Вариант А (рекомендуемый):** Использовать CSV-выгрузку на основе базы Скурихина/Тутельяна или открытых датасетов русскоязычных продуктов (доступны на GitHub, например, репозиторий openfoodfacts-ru или парсинг calorizator.ru в рамках добросовестного использования).

**Вариант Б:** Скрипт на Python, который делает пакетные запросы к `world.openfoodfacts.org/cgi/search.pl?search_terms=яблоко&search_simple=1&action=process&json=1&cc=ru&lc=ru`, извлекая `product_name`, `nutriments` (`energy-kcal`, `proteins`, `carbohydrates`, `fat`).

### Шаг 2: Очистка и нормализация

- Привести все названия к нижнему регистру
- Убедиться, что КБЖУ указаны на 100 грамм продукта
- Заполнить пропуски нулями

### Шаг 3: Импорт в Supabase

- Сохранить очищенные данные в формате `products.csv`
- Использовать встроенный инструмент Supabase Dashboard: Database → Import from CSV в таблицу `nutrition_products`
- Создать индекс в PostgreSQL для ускорения поиска:

```sql
CREATE INDEX idx_product_name_trgm ON nutrition_products USING gin (name_ru gin_trgm_ops);
```

(требуется расширение `pg_trgm`)

### Шаг 4: Администрирование

В админ-панели (Refine/Strapi) должна быть возможность:

- Найти продукт по названию
- Отредактировать его КБЖУ вручную
- Добавить новый продукт
