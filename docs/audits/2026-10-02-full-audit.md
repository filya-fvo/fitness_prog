## 1. Данные и файлы на сервере

Удалён только неиспользуемый Docker build-кэш старше 72 часов: Docker сообщил
**4,526 GB** освобождённого объёма. Занятое место корневой файловой системы
уменьшилось на **4 476 854 272 байта**, заполнение — с **56% до 48%**.
Все девять постоянных сервисов после очистки работают, API отвечает `ok`,
сайт — HTTP 200. Production checkout остался чистым.
Повторный финальный срез: [состояние production после аудита](../../artifacts/full-audit-20261002-server/final-health.log).

Ежедневная копия PostgreSQL от 02.10.2026 восстановлена в отдельном
контейнере без сети; проверены повторное применение миграций и защита audit-log.
Результат — `RESTORE_VERIFY_OK`, 36 таблиц / 5 194 строки в восстановленной копии.
Временный контейнер и volume удалены. Рабочую БД не очищали.

Сохранены журналы текущего периода, backups, volumes, активные образы/модели,
Git-код и ассеты релизов. Крупные кандидаты для отдельного решения: старая модель
Qwen 1.5B около 1,12 GB, backup bundle около 122 MB и накопление журналов
`/var/log` около 5,6 GiB. Их размер сам по себе не доказывает ненужность.
Старая модель не используется текущим запуском, но её роль в rollback вне Git
не установлена. Старые документы в server Git checkout вручную не удалялись:
локальные удаления должны попасть туда штатным будущим выпуском.

## 2. Локальные данные и исторические аудиты

Удалено **1 380 файлов / 107 652 793 байта** — **107,65 MB / 102,67 MiB**:
три оставшихся временных профиля Lighthouse, производный Graphify-кэш,
два orphan `.pyc`, проверочная `.dist-check` и три архивных QA-документа/результата.
Для архивных документов проверено отсутствие активных входящих ссылок;
tracked-версии доступны в истории Git. Для удаляемых каталогов проверены точные
пути внутри проекта и отсутствие reparse points.

Сохранены рабочие зависимости, `frontend/dist`, модели/медиа, Redis snapshot,
backups и существовавшие изменения исходников. Активные старые QA-документы
сохраняются там, где они всё ещё являются ссылкой или output текущего инструмента.
README теперь ведёт на этот аудит.

Существующие E2E имеют жёстко заданные пути снимков: основной прогон записал
**182 PNG** в прежние untracked каталоги design-review/faq-design. Они могли
перезаписать предыдущие generated QA outputs; hashes до запуска не снимались,
поэтому их прежние версии восстановить по этому аудиту нельзя. Это ограничение
сохранности результатов проверки, а не изменение пользовательского дневника
или исходных медиа. Перечень текущих изображений и их hashes сохранён в отдельном manifest.
При завершении все 182 оригинала и копии сверены по SHA256: совпадение полное.
Избыточные новые копии на 82,71 MB удалены; действующие оригинальные изображения
и manifest с hashes/путями сохранены. Дополнительно удалены созданные этим
аудитом временные npm/Python кэши. Эти объёмы не прибавлены к 107,65 MB очистки
существовавших до аудита файлов.

## 4. Пользователи и действия

Созданы **9 настоящих тестовых записей**: male/female/unspecified ×
gym/home/outdoor, с beginner/intermediate/advanced, разными целями и программами,
включая женские настройки цикла. Это свежая временная PostgreSQL 18 + pgvector
и Redis на VPS, отдельная `--internal` сеть без published ports, production
volumes/credentials и фоновых отправителей. Использован текущий runtime API image
с read-only снимком кода/миграций и dummy credentials. Проверка FREE-права
предшествовала временному PLUS-доступу в этой базе.

Выполнены **368 API/status/semantic assertions**, все успешны: программа,
тренировка/подходы/завершение/история, своя тренировка, расписание,
повтор offline-запроса, питание, замеры и дневные показатели, настройки,
поддержка, invitations/friends/block, частные/глобальные соревнования,
запрет admin-доступа и доступ к чужому объекту. Это 368 проверок, а не
368 независимых полных пользовательских путей. Подробные расчёты/границы
приватности дополнительно покрывает существующий unit/E2E набор.
После проверки все временные users/containers/network/files удалены;
тестовые аккаунты не остались в production-базе.

### Зависимости

`npm audit` сообщил 2 high warnings для axios и brace-expansion. Отдельно
официальный [pip-audit](https://github.com/pypa/pip-audit) проверил exact versions
66 локальных и 59 production Python-пакетов без установки/обновления пакетов
приложения. Production содержит advisory для ecdsa; локальное окружение также
имеет предупреждения cryptography, pip, PyJWT и urllib3. Проверялись публичные
названия/версии; секреты и данные пользователей внешним сервисам не передавались.

Применимость, дубли advisory, доступные исправления и runtime paths:
[аудит зависимостей](2026-10-02-dependencies.md). Наличие advisory не доказывает
эксплуатацию приложения; production и local версии отличаются. Автоматическое
обновление зависимостей и новый выпуск не выполнялись.
Python triage: из 19 уникальных локальных advisory 15 не имеют установленного
пути к затронутой операции в рассмотренном коде, 4 требуют дальнейшей проверки
Web Push/proxy и package index. Единственный production advisory относится
к неиспользуемому в текущих рассмотренных подписях fallback ecdsa.
Подтверждённых exploit в рамках этой проверки нет; это не гарантия безопасности.
Временный инструмент/cache удалён после сохранения результатов.
