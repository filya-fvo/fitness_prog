## Подтверждённые кандидаты и ограничения

1. **Системные журналы занимают 5,6 GiB за текущий период.** Нужен отдельный анализ причин роста и согласованный срок хранения: это журнал безопасности/диагностики, его отсутствие использования не доказано. В этом аудите не отключались journald/rsyslog и не сокращалось покрытие мониторинга. Документированный weekly logrotate уже работает; интенсивность текущей записи остаётся предметом последующей диагностики.
2. **`qwen2.5-1.5b-instruct-q4_k_m.gguf` (1 117 320 736 B) не выбрана текущим контейнером LLM.** Его аргументы используют 3B (2 104 932 768 B); ссылки на 1.5B в текущем Git не найдены. Старая модель сохранена как кандидат, поскольку правило проекта исключает каталог models из обычной очистки и независимый rollback-процесс вне Git не проверен. Рабочая модель 3B нужна.
3. **Исторические docs, Windows tools и Graphify snapshot в VPS source** не являются загруженными runtime-модулями, но находятся в canonical Git checkout. Ручное удаление даст dirty source и помешает понятному последующему обновлению. Локальная чистка tracked QA-истории подготовлена отдельно; публикация новой версии проекта в эту задачу не включена.
4. **Резервные копии не классифицированы как мусор.** Сохранены daily/manual и Git bundle 121 622 694 B. Наличие дубликатов/возраст само по себе не подтверждает ненужность точки восстановления. Внешнее/offsite хранение не проверено.

## Состояние и доступы

Production UI показывает версию 0.21.43 / commit 497e92ff3c67; worker/poller heartbeat свежие, очередь пустая, LLM/OCR отвечают. Автоматическая история состояния имеет отдельный дефект доступности host-status у worker — см. D21 [дизайн-отчёта](2026-10-02-design.md). Фактический backup при этом есть и восстановлен.

`backend/.env.production` имеет права 600 root:root; `/root/.ssh` — 700. Вход root существующим ключом работает. SSH server также разрешает root/password authentication; пароль root не извлекался и неизвестен. Этот аудит не менял политику аутентификации.

Пароль PostgreSQL по прямому поручению владельца сохранён отдельно в Git-ignored `C:\fitness_prog\.env.vps-access.local` в формате Windows DPAPI/PSCredential. Открытый пароль не выводился в инструменты/чат/отчёты. Инструкция его просмотра владельцем включена в [VPS_ADMIN_GUIDE](../VPS_ADMIN_GUIDE.md). Пароли Timeweb/root нельзя восстановить из SSH-ключа; их отсутствие не мешает текущему входу по ключу.

IPv6: default route существует через eth0, networkd показывает routable; прямой запрос из API к `https://api.telegram.org/` по IPv6 вернул 302. Runtime `accept_ra=0` отличается от сохранённого sysctl=2: systemd-networkd использует RA в userspace и отключает kernel RA. Нельзя считать один sysctl доказательством отказа. [Первичный источник systemd](https://github.com/systemd/systemd/blob/main/man/systemd.network.xml). Первый запрос из большого диагностического сценария дал 000; отдельным вызовом это не воспроизвелось, постоянный outage не подтверждён.
