# Отчёт о загрузке браузерной версии — 2026-08-20

## Область замера

Замер выполнен на production-сборке Vite командой `npm run build`. Он фиксирует объём ресурсов холодного старта и границы отложенной загрузки. Сетевые TTFB, FCP и LCP зависят от production-хоста, Tailscale Funnel, устройства и канала связи, поэтому их нужно дополнительно снять после развёртывания на реальном адресе.

## До изменений

Начальная HTML-страница заранее загружала:

| Ресурс | Gzip |
|---|---:|
| основной код | 46,09 КБ |
| React и Router | 59,97 КБ |
| IndexedDB/Dexie | 32,51 КБ |
| стили | 6,36 КБ |
| **Итого** | **144,93 КБ** |

Даже до входа по почте приложение загружало домашний маршрут и IndexedDB. Внешний Telegram SDK подключался синхронно и мог задерживать разбор страницы в обычном браузере.

## После изменений

| Ресурс | Gzip |
|---|---:|
| основной код | ≈40,3 КБ |
| React и Router | 59,97 КБ |
| стили | 6,37 КБ |
| **Итого** | **≈106,7 КБ** |

Снижение начального JavaScript и CSS: **примерно 38,3 КБ gzip, или 26,4%**. IndexedDB/Dexie теперь не является module preload и загружается только после входа или действия, которому требуется локальная база. Обязательный PWA precache уменьшен до 340,29 КБ несжатых ресурсов.

Дополнительно:

- гостевой production-экран не создаёт закрытые маршруты до успешной авторизации;
- Telegram SDK загружается с `defer` и не блокирует разбор HTML;
- сканер ZXing остаётся отдельным чанком 108,74 КБ gzip и загружается только при открытии сканера;
- страницы питания, прогресса, профиля и тренировки остаются раздельными lazy-чанками;
- offline-модули исключены из обязательного precache гостевого старта.
- автоматический budget ограничивает сумму всех lazy JS-чанков 432 КБ gzip и
  крупнейший отдельный чанк 140 КБ gzip. После добавления 25 августа визуального
  выбора замены из полного каталога текущие значения — около 411,1 и 108,7 КБ
  соответственно; новая возможность добавила примерно 1,2 КБ gzip без новых
  зависимостей.

Обновление 2026-08-26: отдельный admin-only lazy chunk экрана состояния добавил
2,1 КБ gzip. Суммарный объём всех маршрутов стал 414149 байт, крупнейший chunk
остался 108742 байта. Начальный пользовательский маршрут не увеличился; общий
порог точечно поднят с 412 до 415 КБ. После добавления изолированного журнала
администратора 26 августа порог поднят до 419 КБ, а после отдельной карточки
пользователя 27 августа — до 425 КБ. Изолированный центр рассылок добавил 5818
байт gzip и поднял суммарное фактическое значение до 430850 байт, поэтому общий
порог точечно увеличен до 432 КБ; лимит отдельного chunk сохранён 140 КБ.

Обновление 2026-08-30: связанный поиск журнала и точные переходы к четырём
административным объектам увеличили изолированные admin chunks до 37728 байт
gzip. Лимит admin-only кода откалиброван с 37000 до 38500 байт; общий лимит
455000 байт, product-route лимит 420000 байт и предел отдельного chunk 140000
байт не изменены. Фактический общий объём — 454249 байт, product routes —
416521 байт; новых зависимостей нет.

Обновление 2026-08-31: браузерный вход через Telegram добавлен без новой npm-зависимости;
официальный SDK загружается только после нажатия кнопки входа. Общий объём JS — 454760
байт gzip, product routes — 417033 байта, admin-only — 37727 байт, крупнейший chunk —
108742 байта. Все действующие лимиты сохранены: 455000 / 420000 / 38500 / 140000 байт.

Повторная диагностика production 31 августа отделила сеть от клиентского bootstrap:
HTML имел TTFB 166 мс, `/health` отвечал за 56 мс, а гостевой экран входа становился
доступен примерно через 1,15 с в чистом Chromium. Долгое открытие уже авторизованного
браузера создавал `Shell`: он ожидал `/users/me` до первого рендера и не ограничивал
ожидание. Теперь ранее проверенный профиль отображается из локального кэша сразу,
серверная сверка идёт в фоне с timeout 8 секунд, а просроченный JWT удаляется после
`401/403`. Chromium E2E удерживает `/users/me` незавершённым и подтверждает, что
Главная уже доступна до ответа сервера.
После исправления общий объём JS составляет 454957 байт gzip, product routes —
417228 байт, admin-only — 37729 байт; действующие лимиты не увеличивались.

## Проверка после развёртывания

Для Chrome DevTools использовать профиль Mobile / Fast 4G с отключённым кэшем и выполнить по три запуска:

1. `/` без сессии — время до доступного поля email;
2. `/` с сессией — время до первого действия на Главной;
3. `/nutrition` и `/progress` — первый и повторный переход;
4. `/help` без сессии — прямое открытие справки;
5. отдельно Telegram WebView на Android и iOS.

Зафиксировать p75 по реальным визитам: TTFB до 800 мс, LCP до 3 секунд и отклик основного действия до 200 мс. Если TTFB выше цели при малом клиентском объёме, отдельно проверять backend/Funnel и время авторизации.
