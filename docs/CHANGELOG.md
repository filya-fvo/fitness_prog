## 0.20.42 — 2026-08-28

### Управляемые рассылки и безопасный Telegram-smoke

- Запланированную рассылку теперь можно отменить до начала отправки. Ожидающие
  доставки получают конечный статус, а отмена сохраняется в immutable audit.

  аудитории отменяет устаревшие запросы и очищает прежнюю ошибку после успеха.
- История показывает отменённые сообщения и агрегированные безопасные причины
  недоставки без сырого ответа Telegram.
- Добавлен opt-in smoke реальной связи: без `--write` он только проверяет
  выделенного получателя из `ADMIN_SMOKE_TELEGRAM_ID`, а с флагом отправляет
  ровно ему служебное сообщение, руководство и тестовую рассылку.

## 0.20.41 — 2026-08-28

### Доказательный ИИ-анализ вместо одинакового ответа

- Сервер теперь различает вопросы о тренировочном и силовом прогрессе, весе,
  обхватах, питании, восстановлении, безопасности и общие вопросы. Исходный
  вопрос участвует в анализе, а «за месяц» означает 30, а не 14 дней.
- В локальный Qwen передаются только агрегаты нужного периода: точки и дельты
  замеров, тренд веса, средние КБЖУ и заполненность, сон/шаги/активность/вода,
  тренировки, RPE и показатели упражнений. При отсутствии фактов приложение
  задаёт один уточняющий вопрос без выдуманного отчёта.
- Backend и frontend используют одинаковую математику тоннажа: вес «на руку»
  удваивается, обычный вес не меняется, повторы без веса и работа по времени
  учитываются отдельно.

### Проверка

- Полный backend pytest: **285 passed**; Ruff: без ошибок.
- Полный frontend Vitest: **208 passed**; ESLint и TypeScript/PWA production
  build прошли.

## 0.20.39 — 2026-08-28

### Безопасные черновики и версии программ

- Общий каталог теперь возвращает только текущие опубликованные версии. Пустой
  черновик из админки больше не может появиться у пользователя или запуститься.
- Добавлен жизненный цикл `draft → published → archived`: публикация проверяет
  дни, упражнения, подходы, повторения, отдых, пол, уровень, место, инвентарь и
  ограничения. Опубликованная версия не редактируется на месте — создаётся новый
  черновик, а закреплённая у пользователя предыдущая версия остаётся доступна.
- Добавлены безопасная публикация, возврат предыдущей версии, preview через тот
  же сборщик плана, которым начинается настоящая тренировка, и неизменяемые
  события административного аудита.
- Legacy-форма теперь создаёт явно обозначенный черновик; опубликованные записи
  нельзя случайно менять её выпадающими списками.
- Seed-процессы явно публикуют доверенный версионированный каталог. Миграция
  переводит в опубликованные только существующие программы с непустым и
  согласованным расписанием.

## 0.20.34 — 2026-08-27

### Вес в замерах и корректный старт расписания

- Вес убран из ежедневной карточки **Активность и восстановление** и её графиков.
  Теперь вес вводится и анализируется в **Ещё → Замеры тела** вместе с обхватами;
  профиль показывает его без второй формы редактирования.
- Новая миграция переносит все существующие записи веса из `daily_metrics` в
  `body_measurements`, обновляет текущий вес профиля по последнему замеру и только
  после этого удаляет старый столбец. Последующие замеры веса участвуют в расчёте
  калорий и макронутриентов через актуальный профильный снимок.
- Для уже открытых Telegram/PWA-версий сохранены переходные поля старого API:
  они получают `weight_kg: null`, но новые записи веса принимаются только через
  API замеров. Старое имя счётчика веса в админке временно возвращается вместе с новым.
- Календарь тренировок больше не ищет пропуски раньше даты старта активной
  программы или создания аккаунта. Выбор другой программы сбрасывает её на первый
  день и фиксирует новую дату старта, поэтому созданный в четверг план с первым
  днём в пятницу не показывает прошедшую среду как пропущенную тренировку.

## 0.20.33 — 2026-08-27

### Admin 4: центр рассылок

- Добавлен отдельный экран **Центр рассылок** с редактором, безопасным

  ожидает, отправляется, доставлена, ошибка или пропущена. История обновляет
  прогресс, переключается страницами и позволяет копировать прошлую кампанию.
- ARQ worker отправляет последовательно пакетами до 20 адресатов с Redis-lock и
  интервалом между Telegram-вызовами. Блокировка бота и недоступный чат считаются
  окончательным пропуском; временные ошибки можно повторить отдельно без повторной
  отправки уже успешным получателям.
- Добавлены idempotency key кампании, уникальность пары кампания/получатель,
  безопасное возобновление очереди и append-only audit без текста сообщения.
  Новая миграция создаёт `admin_broadcasts` и `admin_broadcast_deliveries`.

## 0.20.31 — 2026-08-27

### ESTT исключён из вариантов production

- После проверки ответа поддержки отказались от переноса на ESTT: Telegram API
  недоступен с выданной ноды, а перенести VPS на другую ноду провайдер не может.
- В руководстве Timeweb зафиксирован как фактический production, Beget оставлен
  резервным вариантом, а ESTT запрещён для переноса секретов и пользовательской БД.
- На ESTT находился только синтетический staging без production-секретов и
  пользовательских данных; рабочий Timeweb не переключался и продолжает работу.

### Проверка

- Документация проверена поиском активных упоминаний ESTT и противоречащих
  рекомендаций по основному production-провайдеру.

- Merge выполняется одной транзакцией с блокировкой обеих записей. Telegram-аккаунт остаётся единственной активной записью, почтовая запись помечается объединённой и удалённой, а её прежний идентификатор сохраняется для аудита и очистки локального кэша.
- Дубликаты тренировок с одинаковым клиентским ID и слоты добавок объединяются без нарушения уникальных ограничений; подписка и баланс Stars не понижаются и не теряются.

### Актуальный URL в уведомлениях

- Фоновый worker уведомлений теперь перечитывает конфигурацию перед каждым заданием и не продолжает отправлять Open-кнопки со старым URL после изменения `MINI_APP_URL`.

### Ввод дробных чисел

- Во всех полях с дробными значениями теперь одинаково принимаются точка и запятая: например, `12.5` и `12,5` сохраняются как одно и то же число.
