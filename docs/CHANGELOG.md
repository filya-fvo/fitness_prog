## 0.18.6 — 2026-08-14

### Питание и расширенный каталог программ

- В дневнике питания кнопка **«Закрыть добавление»** перенесена в конец формы, сразу под **«Добавить и продолжить»**; закреплённая кнопка теперь служит только для открытия формы.
- Добавлены 14 программ — по мужской и женской версии семи схем: антагонисты 3 дня, пятидневный сплит, четырёхдневное чередование акцентов, Тяни/Жми, только тренажёры, Full Body 2 дня для новичка и Powerbuilding.
- Четырёхдневное чередование сохраняет строгий круг «грудь → ноги → спина → плечи» и допускает 3–6 тренировок в неделю с днями отдыха между ними.
- Каталог расширен с 52 до 66 программ; генератор и тесты закрепляют наличие новых схем для обоих полов, число дней и машинный инвентарь соответствующего плана.

## 0.18.5 — 2026-08-14

### Полный аудит анимаций упражнений

- Все 124 упражнения каталога сопоставлены с исходным набором: каждый отображаемый GIF теперь имеет единственный тег `ds:*`, а имя файла автоматически проверяется по исходной записи набора.
- Исправлены анимации «Тяги верхнего блока обратным хватом» и «Пуловера в блоке на спину»; они больше не используют один неподходящий вариант тяги стоя.
- Отдельные точные GIF назначены вариантам французского жима со штангой, EZ-грифом и стоя, разгибанию рук из-за головы на блоке и жиму вниз на блоке канатом.
- Исправлены анимации планки с касанием плеч и беговой дорожки: используются соответственно обычная высокая планка и тренажёр, а не вариант с колен и бег без дорожки.
- Для 12 движений, которых нет в исходном наборе в достаточно точном виде, приблизительные и вводящие в заблуждение GIF отключены. Интерфейс показывает технику без чужой анимации.
- Генераторы каталога и тесты изменены так, чтобы повторное обновление контента не возвращало приблизительные файлы.

## 0.18.4 — 2026-08-14

### Таймер отдыха, автопереход и анимация упражнения

- Запись нового подхода, «Как прошлый» и добавление подхода больше не перезапускают уже идущий таймер отдыха и не заменяют текст запланированного уведомления.
- Устранено двойное планирование одного уведомления при повторном запуске эффекта интерфейса; при сетевой ошибке сохраняется резервная отправка в момент окончания таймера.
- Автопереход срабатывает после последнего планового подхода, даже если пользователь ранее добавил дополнительный незавершённый подход; повторное завершение дополнительных подходов не запускает второй отсчёт.
- Настройка автоперехода кешируется на устройстве и продолжает действовать при временной ошибке загрузки профиля.
- Для «Тяги верхнего блока» установлена соответствующая технике анимация классического варианта сидя вместо варианта стоя в полной амплитуде.

## 0.18.3 — 2026-08-14

### Бесплатный production-режим на ноутбуке

- Публичное приложение переведено с Vite dev server на production-сборку, которую FastAPI обслуживает вместе с API и Telegram webhook на одном локальном порту `8001`; Tailscale Funnel теперь направлен туда же.
- Добавлены отдельные сценарии `dev-local.cmd` и `publish-local.cmd`: supervisor приостанавливается на время разработки и снова включается после проверенной сборки.
- Supervisor и диагностика больше не требуют постоянно работающий Vite `:5173`; восстановление проверяет единое приложение, Redis, worker и Funnel.
- Маршруты экранов `/programs`, `/workouts`, `/nutrition`, `/ai` и `/admin` корректно отличаются от одноимённых API по типу запроса; неизвестный API больше не получает HTML вместо `404`.
- Экраны разбиты на ленивые chunks: основной JavaScript-файл уменьшен примерно с 510 до 149 КБ, а сканер штрихкода загружается только при открытии питания.
- PWA больше не скачивает заранее GIF упражнений и тяжёлые функциональные chunks; стартовый precache ограничен оболочкой приложения.
- Повторный bootstrap Telegram использует один auth-запрос, а backend сериализует одновременное создание одного Telegram-пользователя, исключая гонку уникального идентификатора.
- Production-launcher явно закрепляет Funnel за `:8001`, даже если старый адрес на `:5173` ещё отвечает, и автоматически создаёт отсутствующий секрет Telegram webhook без вывода его значения.

## 0.18.2 — 2026-08-13

### Адрес сайта и отдельная инструкция администратора

- Приветствие `/start` теперь показывает актуальный кликабельный HTTPS-адрес для входа через обычный браузер и поясняет регистрацию по электронной почте.
- Пользовательская инструкция очищена от настроек backend, worker, webhook и AI-провайдеров; в ней остались пользовательские сценарии и устранение типовых проблем.
- Добавлена скрытая команда `/admin`: она отсутствует в меню команд и доступна только Telegram ID/username из настроек администраторов. Команда отправляет отдельную инструкцию запуска и диагностики.
- Полный launcher теперь проверяет реальную доступность сохранённого Tailscale Funnel, при сбое повторно включает его и ждёт публичные `/` и `/health` до обновления Telegram. Повторный запуск launcher больше не создаёт второй worker уведомлений.
- Добавлен системный `Fitness App Supervisor`: автозапуск вместе с Windows, штатная блокировка сна без имитации активности, проверка локальных сервисов и публичного URL, восстановление Tailscale/Funnel, Redis и worker, журнал и команды паузы/возобновления.

### Регистрация по почте и безопасное объединение аккаунтов

- В браузере теперь можно первым шагом зарегистрироваться по электронной почте: после подтверждения одноразового кода создаётся полноценный аккаунт без обязательного предварительного входа через Telegram.
- Если позже пользователь входит через Telegram и подтверждает ту же почту, приложение обнаруживает две записи и показывает предварительное сравнение: конфликты профиля и количество тренировок/записей питания с каждой стороны.
- До явного выбора пользователя объединение не выполняется. Можно выбрать приоритет профиля «из почты» или «из Telegram»; история тренировок, подходов, питания, чата, добавок и push-подписок сохраняется с обеих сторон независимо от выбора.
- Merge выполняется одной транзакцией с блокировкой обеих записей. Telegram-аккаунт остаётся единственной активной записью, почтовая запись помечается объединённой и удалённой, а её прежний идентификатор сохраняется для аудита и очистки локального кэша.
- Дубликаты тренировок с одинаковым клиентским ID и слоты добавок объединяются без нарушения уникальных ограничений; подписка и баланс Stars не понижаются и не теряются.

### Актуальный URL в уведомлениях

- Фоновый worker уведомлений теперь перечитывает конфигурацию перед каждым заданием и не продолжает отправлять Open-кнопки со старым URL после изменения `MINI_APP_URL`.
- Генератор всех Telegram-кнопок дополнительно отклоняет HTTP-адреса и любые ngrok-хосты; приветствия, напоминания, таймеры и плановые уведомления используют единый безопасный источник URL.

### Ввод дробных чисел

- Во всех полях с дробными значениями теперь одинаково принимаются точка и запятая: например, `12.5` и `12,5` сохраняются как одно и то же число.
- Исправление охватывает рабочие веса и шаговые контролы, параметры кардиотренажёров и разминки, вес и замеры тела, сон, граммы и БЖУ продуктов, а также редактирование истории тренировок.
- Во время ввода сохраняется промежуточное значение вроде `12,`, поэтому Telegram WebView больше не сбрасывает дробную часть после нажатия запятой.

### Публичный адрес Mini App

- Бесплатный ngrok заменён в основном сценарии запуска на Tailscale Funnel с постоянным HTTPS-адресом без промежуточной страницы-предупреждения.
- `start-all.cmd` автоматически запускает Funnel, сохраняет публичный URL, обновляет `MINI_APP_URL`, Telegram Menu Button и webhook.
- Добавлен отдельный безопасный запускатель `scripts/start-tailscale-funnel.ps1`; секреты и токены Tailscale в проект не записываются.
- Старый ngrok-сценарий отключён; устаревшая команда завершается с подсказкой использовать Tailscale Funnel.
- Удалены автоматические fallback на старые ngrok URL; попытка настроить такой адрес теперь блокируется.
- При запуске синхронизируются не только общая, но и персональные Telegram Menu Button всех известных пользователей — старый override чата больше не сохраняет ngrok.
- Добавлены отправка свежей Open-кнопки выбранному пользователю и комплексная проверка совпадения Funnel, `MINI_APP_URL`, webhook и Telegram Menu Button.
- Создана полная инструкция администратора локального Windows-сервера: установка, первый запуск, ежедневная работа, Tailscale, BotFather, уведомления, диагностика и безопасность.
- Добавлена управляемая рассылка нового `/start`-эквивалента всем привязанным пользователям: свежая inline-кнопка и обновлённая постоянная клавиатура Open, `/start`, `/help` без попытки удалить историю чата.

### Откат дня программы после удаления

- Удаление тренировки активной программы теперь всегда возвращает цикл к удалённому дню: например, после удаления «Тяга B» следующим снова будет «Тяга B», а не «Ноги B».
- Откат больше не зависит от текущего значения курсора, порядка сетевых обновлений или наличия более поздней тренировки.
- Восстанавливаются фаза нагрузки и число выполненных дней внутри фазы; старые тренировки без `day_index` распознаются по названию дня программы.
- Удаление тренировки из другой, неактивной программы не меняет текущий цикл.

## 0.18.1 — 2026-08-13

### Русская терминология и пояснения

- Проведён аудит пользовательских текстов во всех основных разделах: тренировки, каталог, программы, прогресс, питание, профиль, уведомления, ИИ-чат и админ-панель.
- Сырые значения статусов, уровней, целей, тарифов, типов программ, источников медиа, групп мышц и оборудования переведены единым модулем локализации.
- RPE и RIR теперь сопровождаются русскими названиями и объяснениями; `est. 1RM / Epley` заменено на «расчётный одноповторный максимум (1ПМ) по формуле Эпли» с предупреждением, что это оценка.
- Термины `BMR` и `TDEE` в интерфейсе заменены на «энергия в покое» и «общий суточный расход»; Б/Ж/У раскрыты до белков, жиров и углеводов с единицами измерения.
- Пользовательские надписи `AI`, `email`, `GIF`, `Web Push`, `offline`, `soft-delete` заменены понятными русскими формулировками. Бренды Telegram, YouTube и названия почтовых адресов сохранены.
- Технические теги упражнений (`ds:*`, `gymvisual`, служебные источники) скрыты; полезные признаки вроде «на время» и «на одну сторону» переведены.
- Англоязычные сообщения ошибок основных API заменены русскими, а клиент больше не показывает пользователю преимущественно англоязычные технические исключения.

### Достоверная история тренировок

- Дни календаря прогресса теперь открываются. Карточка дня показывает название и фазу тренировки, длительность, RPE, выполненные упражнения, каждый подход, вес, повторы, режим веса, заметки и суммарный объём.
- Завершённую тренировку можно исправить: изменить RPE, заметку, веса, повторы и комментарии к подходам. После сохранения кэш и вся аналитика используют исправленные данные.
- Прошлую или ошибочно начатую тренировку можно удалить с подтверждением. Используется soft delete; запись и её подходы исчезают из истории, серии, объёма и AI-контекста. При удалении последней завершённой тренировки активной программы её курсор безопасно возвращается на удалённый день.
- В активной тренировке появилась команда «Отменить и удалить тренировку». Она не завершает тренировку и не продвигает следующий день программы; офлайн-отмена отправляется через очередь синхронизации.
- AI получил жёсткий контракт русского языка. Ответ без русского текста отклоняется, после чего пользователь получает безопасный русскоязычный локальный ответ.
- Обновление сетевого списка теперь удаляет устаревшие тренировки из пользовательского офлайн-кэша, поэтому удалённая запись не возвращается без сети.

### Надёжность офлайн-режима и авторизации

- Локальные тренировки, незавершённые сессии и очередь синхронизации разделены по внутреннему UUID пользователя. После смены аккаунта приложение не показывает и не отправляет данные предыдущего пользователя.
- Офлайн-изменения профиля и онбординга включены в общую очередь и автоматически отправляются после восстановления сети. Новое изменение профиля заменяет старый несинхронизированный черновик.
- Создание тренировки получило `client_workout_id` и серверную идемпотентность; повтор завершения уже завершённой тренировки возвращает текущее состояние без вечной ошибки очереди.
- Вход по email разрешён только для предварительно привязанной почты. Неизвестный адрес больше не создаёт отдельный browser-only аккаунт.
- Production API больше не сообщает об успешном OTP, если SMTP не доставил письмо; добавлены блокировка параллельных запросов одного кода и почасовой лимит по IP.
- Сервер валидирует биометрию, цели и числовые пределы тренировок/питания до записи в БД.
- Замена фоновой задачи таймера защищена Redis-lock, а массовая рассылка worker обходит всех пользователей пакетами вместо скрытого ограничения в 5000.
- HTTP-логи API и worker маскируют Telegram Bot API token и Bearer credentials до записи на диск.
- Добавлена миграция `20260813000015_workout_idempotency.sql` и регрессионные тесты найденных QA-дефектов.

## 0.18.0 — 2026-08-12

### Учёт добавок и уведомления

- Добавлен журнал приёмов добавок со статусами «ожидает / принято / пропущено», единый для Mini App и Telegram.
- Одновременные добавки приходят одним Telegram-сообщением, но отмечаются независимо; доступны «Принял всё» для конкретного времени и перенос оставшейся группы на 30 минут.
- Регистрация Telegram webhook теперь явно включает `callback_query`, поэтому кнопки подтверждения, пропуска и переноса приёма действительно передаются в backend.
- В профиле появился блок приёмов на сегодня с группировкой по времени и возможностью отменить отметку. Дата определяется по часовому поясу профиля, а смена расписания перестраивает только ожидающие записи, сохраняя завершённую историю.
- Для пользователей браузера добавлен стандартный Web Push с отдельной подпиской каждого устройства. На iOS/iPadOS показано требование установить PWA на экран «Домой».
- Добавлены миграция `20260812000013_supplement_intakes_web_push.sql`, VAPID-конфигурация API/worker и инструкция администратора.

### Тренировка и таймер

- Таймер отдыха переведён с накопительного `setInterval` на абсолютное время окончания и восстанавливается после сворачивания или повторного открытия приложения.
- При запуске отдыха backend ставит отложенную ARQ-задачу: при полностью закрытом приложении завершение приходит через Telegram и/или Web Push. Изменение времени заменяет задачу, остановка отменяет её.
- Защищено двойное нажатие «Готово»: один подход не может повторно запустить таймер или отправить два сохранения.
- Автоматический переход стал выключаемой профильной настройкой. При включении после последнего планового подхода показывается трёхсекундный отсчёт с отменой для дополнительного подхода.
- На активной карточке показана группа мышц. План упражнений на сегодня на главной по умолчанию свёрнут и раскрывается по нажатию; из раскрытого списка доступны полное описание и GIF до старта.
- Для гантелей добавлен явный режим веса «на 1 гантель / общий вес», сохраняемый в `workout_sets.weight_mode`; добавлена миграция `20260812000014_workout_set_weight_mode.sql`.

## 0.17.0 — 2026-08-11

### Щадящая нагрузка на плечевые суставы
- В онбординг и раздел профиля «Тело и цели» добавлено ограничение «Щадящая нагрузка на плечевые суставы» (`shoulder_sensitive`) с явной оговоркой о безболезненной амплитуде и консультации со специалистом.
- Добавлены 10 программ: дом для мужчин и женщин на двух уровнях, зал для мужчин и женщин на начальном, среднем и продвинутом уровнях. Все дни содержат 6–7 упражнений.
- В этих планах исключены жимы и тяги верхней части тела, движения над головой, отжимания, подтягивания и упоры на руки; акцент перенесён на ноги, ягодицы, икры, кор и изоляцию рук у корпуса.
- Подбор программ, фильтр «Под мои ограничения», бейджи, предупреждение о несовместимости и массовая замена упражнений учитывают новый профиль.
- Генератор теперь сохраняет две ранее существовавшие трёхдневные силовые программы, поэтому регенерация seed больше не удаляет их. Seed повторно активирует совпавший архивный шаблон с прежним ID, не ломая закреплённую у пользователя программу. Итоговый каталог содержит 52 программы.

### AI-тренер
- Основная бесплатная модель Groq заменена с уходящей `llama-3.1-8b-instant` на `qwen/qwen3.6-27b`.
- Обычный чат использует режим без reasoning, а анализ прогресса — стандартный reasoning. Ответ ограничен 600 токенами для контроля задержки и бесплатной квоты.
- Обновлены локальная конфигурация, production/development-примеры и fallback-значения backend.
- Устранён ложный RAG-контекст: вместо поиска полного предложения и случайной выдачи трёх простейших упражнений используется нормализованный поиск по словам и русским окончаниям; при отсутствии совпадений каталог остаётся пустым.
- AI теперь получает активную программу и следующий день, три последние тренировки с фактическими весами/повторами/RPE и восемь сообщений текущей сессии. Записанная история диалога действительно участвует в следующем ответе.
- Удалён 24-часовой кэш ответов, который не учитывал изменение тренировки, а также неиспользуемое дублирующее состояние `sessionId` на frontend.
- Замены упражнений теперь синхронизируют изменённый `Workout.plan` с сервером, включая offline-очередь, и переносят пустые слоты подходов на замену. AI явно видит связь «замена вместо исходного» и не считает исходное упражнение пропущенным.
- Исправлена существующая Legs A: болгарские выпады сохранены как выполненная замена выпадов назад; пустые старые слоты исключены из AI-контекста без удаления истории.
- AI-чат восстанавливает с сервера до 200 сообщений за текущие локальные сутки и продолжает последнюю сессию после закрытия экрана или Mini App. Ответы анализа прогресса теперь также записываются в историю; чтение истории не расходует AI-квоту.
- Провайдер AI переключён с Groq/Qwen на OpenAI Responses API и наиболее дешёвую актуальную текстовую модель `gpt-5-nano`. Предыдущие Groq-переменные оставлены закомментированными в env-шаблонах для отката.
- На первого AI-запрос пользователя создаётся отдельный OpenAI Conversation, связанный с внутренним UUID через `users.openai_conversation_id`; другой пользователь получает другой диалог. Добавлена миграция `20260811000012_openai_user_conversations.sql`.

- В чате отображается источник ответа: Groq или локальный fallback. «Разбор недели: объём и восстановление» направляется в фактический анализ прогресса, а не в общий чат.
- В Render Blueprint добавлены отсутствовавшие переменные LLM для будущего production-развёртывания.
- Добавлена отдельная инструкция администратора `docs/ADMIN_AI_MODEL_RUNBOOK.md`: выбор и замена модели OpenAI локально/в production, проверка, диагностика и безопасный откат без удаления пользовательских диалогов.
- В инструкции разделены ошибки OpenAI `credit_balance_exhausted` и `rate_limit_exceeded`; отдельно отмечено, что создание ключа и подписка ChatGPT не пополняют баланс Platform API.
