## D-01 — подтверждение выполнения

- Алгоритм рекомендаций исключает программу, если она покрывает лишь часть
  выбранных ограничений.
- Правило действует и в онбординге, и в блоках рекомендаций каталога.
- Пользователь не теряет заполненную анкету, если подходящего готового плана нет.
- Общий каталог остаётся доступен для осознанного ручного выбора.
- Негативный E2E-сценарий проверяет отсутствие `active_program_id`, пояснение и
  переход к полному списку.

Проверки: backend — 530 тестов и Ruff; frontend — 550 unit-тестов, ESLint,
TypeScript/PWA build, bundle budget и 90 Playwright-сценариев.

## D-02 — подтверждение выполнения

## I-04 — подтверждение выполнения

- Общий Axios client ограничивает обычный запрос 15 секундами, поэтому зависшее
  соединение больше не оставляет экран в бесконечной загрузке.
- Локальный ИИ получает до 90 секунд, OCR этикетки — до 60 секунд, загрузка файлов —
  до 45 секунд; Telegram-авторизация сохраняет собственный предел 20 секунд.
- Ошибки Axios `ECONNABORTED` и `ETIMEDOUT` преобразуются в короткое сообщение
  «Сервис отвечает слишком долго. Попробуйте ещё раз.»
- Создание обращения сохраняет ключ операции после временного сбоя. Повтор с тем же
  содержимым использует тот же ключ, а backend возвращает существующую запись без
  второй записи в БД.
- Browser E2E удерживает первый POST без ответа до клиентского таймаута, повторяет
  отправку и проверяет совпадение idempotency key двух запросов.

Проверки I-04: backend support tests, frontend unit-тесты, ESLint, TypeScript/PWA
build, bundle budget и отдельный Chromium-сценарий зависшего API с повтором.

## DB-01 — подтверждение выполнения

- Docker CI поднимает чистые `pgvector/pgvector:0.8.6-pg18-bookworm` и
  `redis:7.4-alpine`, применяет весь набор миграций, повторяет migration runner и
  отдельно запускает `verify_stage_c_integration.py` из production API image.
- Реальная транзакция создаёт тестового пользователя, принудительно откатывается,

- Четыре одновременных сеанса создают тренировку с одним
  `(user_id, client_workout_id)` и получают один UUID при одной строке в БД.
  Тот же `client_workout_id` для второго пользователя создаёт независимую строку.
- Архивирование пользователя освобождает case-insensitive email только для новой
  активной записи; в БД остаются одна архивная и одна активная запись.
- Реальные UPDATE и DELETE тестовой записи `admin_audit_log` отклоняются
  append-only trigger внутри savepoint, а внешняя транзакция затем откатывается.
- В настоящем Redis восемь конкурентных захватов одной минуты дают ровно одного
  победителя; ключ имеет ограниченный TTL и удаляется после проверки.
- Probe имеет 90-секундный предел и отказывается запускаться без `CI=true`,
