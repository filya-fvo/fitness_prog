# Добавки: Telegram и Web Push — инструкция администратора

## Что нужно для запуска

1. Применить миграции: `powershell -ExecutionPolicy Bypass -File scripts/apply_migrations_local.ps1` локально или выполнить новые SQL-файлы в Supabase по порядку.
2. Установить backend-зависимости: `backend\.venv\Scripts\python.exe -m pip install -e backend`.
3. Запустить API, Redis и `arq app.tasks.notifications.WorkerSettings`. Без worker расписание сохраняется, но автоматическая отправка не выполняется.
4. Повторно установить Telegram webhook обычным проектным скриптом. Скрипт регистрирует события `message` и `callback_query`; без второго типа inline-кнопки не придут в backend.

## Настройка Web Push (VAPID)

Один раз создайте пару ключей:

```powershell
Set-Location backend
.\.venv\Scripts\vapid.exe --gen
.\.venv\Scripts\vapid.exe --applicationServerKey
```

Значение `Application Server Key` — это `WEB_PUSH_VAPID_PUBLIC_KEY`. Содержимое `private_key.pem` задайте в `WEB_PUSH_VAPID_PRIVATE_KEY`; в однострочном env переносы можно записать как `\n`. `WEB_PUSH_VAPID_SUBJECT` должен быть контактным `mailto:...` или HTTPS URL.

API и worker обязаны использовать одну и ту же пару:

```env
WEB_PUSH_VAPID_PUBLIC_KEY=...
WEB_PUSH_VAPID_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----
WEB_PUSH_VAPID_SUBJECT=mailto:admin@example.com
```

Не публикуйте приватный ключ и не добавляйте реальный `.env` или `private_key.pem` в Git. При замене пары все прежние браузерные подписки перестанут работать: пользователям потребуется выключить и снова включить уведомления.

## Проверка после развёртывания

1. Откройте Mini App по HTTPS и в **Профиль → Уведомления** включите браузерные уведомления.
2. Назначьте креатин и протеин на одинаковое ближайшее время; включите уведомления добавок.
3. Нажмите «Проверить напоминания сейчас» после наступления времени либо дождитесь worker.
4. Проверьте одно Telegram-сообщение с двумя именными кнопками, «Принял всё» и «Через 30 минут».
5. Нажмите только «Креатин»: в сообщении и в блоке «Сегодня» креатин должен стать принятым, протеин — остаться ожидающим.
6. Нажмите протеин почти одновременно со второй кнопкой: обе операции идемпотентны и не перезаписывают статус соседней добавки.
7. Для браузерного аккаунта без Telegram проверьте системное уведомление при закрытой вкладке. На iOS/iPadOS тест выполняется из PWA, установленной на экран «Домой».

## Тренировки и разовые переносы

- Постоянные дни, локальное время начала и `remind_before_minutes` находятся в `users.goals.notification_settings.workouts`.
- Разовые исключения находятся в `users.goals.workout_schedule_overrides`. Это не тренировки в истории: запись `workouts` создаётся только при фактическом старте.
- `POST /workouts/schedule/reschedule` разрешает перенос только до дня перед следующей постоянной тренировкой. Курсор программы и последующие дни не меняются.
- После переноса backend удаляет только ожидающие приёмы добавок исходной и новой даты. Принятые/пропущенные записи и добавки с обычным ежедневным временем не переносятся задним числом.
- Worker рассчитывает уведомление от фактического времени начала. Если пользователь начал тренировку раньше, будущий reminder помечается обработанным и не отправляется.

Проверочный сценарий: график Пн/Ср/Пт, начало 06:15, reminder за час. Перенесите пятницу на субботу 08:00. В пятницу workout-day/pre-workout уведомлений быть не должно; в субботу напоминание о тренировке ожидается в 07:00, pre-workout за 45 минут — в 07:15; понедельник остаётся тренировочным днём.

## Административные рассылки

- Центр находится в **Ещё → Админ → Центр рассылок** и использует тот же ARQ
  worker, Redis и Telegram Bot API, что и напоминания.
- Примените миграцию `20260827000024_admin_broadcasts.sql` до перезапуска API и
  worker. API без таблиц кампаний не должен публиковаться.
- Массовая отправка идёт пакетами до 20 получателей с ограничением скорости.
  Не запускайте второй worker вручную для ускорения: Redis-lock намеренно не даёт
  обрабатывать одну кампанию параллельно.
- Статус **Пропущено** означает окончательно недоступный Telegram-чат: блокировку
  бота, удалённый аккаунт или `chat not found`. **Ошибка** означает временный сбой
  API/сети и допускает ручной повтор только этих доставок.
- Если Redis был недоступен после сохранения запуска, кампания остаётся в статусе
  **Ожидает**. После восстановления очереди нажмите **Возобновить очередь**;
  уникальные job/recipient keys исключают повтор успешных отправок.
- Текст кампании не записывается в audit-журнал и логи worker. Для диагностики
  используйте ID кампании, безопасный код ошибки и итоговые счётчики.

## Диагностика

- `GET /notifications/push/config` показывает `enabled=true`, только когда оба VAPID-ключа заданы.
- HTTP 404/410 от push-сервиса отключает устаревшую подписку; после пяти других ошибок она также отключается. Повторное включение в профиле восстанавливает её.
- Если нет ни Telegram, ни активной Web Push-подписки, приём не помечается отправленным и worker попробует снова.
- Нажатия Telegram проверяются по `telegram_id` пользователя: чужой callback не может изменить приём.
- Все времена хранятся в UTC, но календарный день и отображение вычисляются в часовом поясе профиля.
