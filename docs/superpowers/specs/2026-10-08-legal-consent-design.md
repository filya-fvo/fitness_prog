# FilFit: базовые документы и однократное подтверждение

Дата: 2026-10-08. Дизайн для проверки владельцем; реализация механизма ещё не начата.

## Согласованный результат

Три самостоятельных документа для одного аккаунта в Telegram/web/APK: политика обработки и защиты персональных данных, базовое согласие на обработку обычных данных, оферта бесплатного использования без условий оплаты. Реквизиты предоставлены владельцем. Специальное письменное согласие на сведения о здоровье/цикле отложено прямым решением владельца; базовый этап не объявляется правовым основанием этой обработки.

Новый аккаунт и существующий пользователь получают одинаковое окно после установления сессии, до дневника и онбординга. Три независимые выключенные отметки: ознакомление с Политикой, отдельное согласие, принятие оферты. Документы доступны до входа и через постоянные ссылки. Можно открыть каждый текст и отказаться/выйти; закрытие окна не создаёт принятия. Повторного запроса после входа, перезапуска, смены устройства или переустановки нет для уже принятой редакции.

## Источник текстов

Канонические MD находятся в frontend/src/features/legal/documents. Общий React импортирует их как plain text и отображает безопасно, без HTML-инъекции. Backend image упаковывает эти же файлы для проверки редакции/контрольной суммы. После утверждения убрать отметку «Проект» из окончательных текстов до вычисления published hash. Предыдущие опубликованные редакции не переписываются; существенный пересмотр меняет consent revision явно.

## Сохранение и совместимость

Новая append-only миграция и отдельная модель записей принятия: user_id, document_id, revision, text_sha256, accepted_at UTC. Ограничение уникальности делает повторный сетевой запрос идемпотентным. Каждая отметка даёт отдельную запись, без общего «согласия со всем». Сервер связывает подтверждение с проверенным JWT, отвергает чужой user_id, неизвестный документ/старый текст/неполный или ложный набор отметок. Согласие не проставляется автоматически существующим пользователям.

GET /legal/status и POST /legal/accept работают с текущими версиями. Состояние включается в auth/user profile для общего bootstrap и owner-scoped offline cache. История подтверждения не заменяется localStorage-флагом. Уже подтверждённый пользователь может открыть закэшированный дневник офлайн. Неподтверждённый пользователь должен дождаться сети для сохранения; ошибка оставляет отметки видимыми и предлагает повтор.

Дневник и очередь не очищаются. Отказ не удаляет аккаунт. Переключение аккаунта отбрасывает старое состояние/ответ. Для старых APK требуется обновление, чтобы увидеть окно; очередь сохраняется. На базовом этапе подтверждение ограничивает вход в интерфейс, но не вводит общее ограничение API: сохранённые тренировки и офлайн-очередь должны безопасно синхронизироваться, в том числе со старого клиента. Принимать документы можно только через отдельный проверяемый API. Серверное блокирование всех операций до подтверждения не входит в этот этап. При появлении окна активная тренировка сохраняется и доступна после подтверждения.

## Порядок выпуска

Сначала web/backend: миграция, документы, окно, профиль и тесты. Затем verified upstream commit → shared pin Android → native legal transport/offline/session regression → APK с тем же owner key и production origin. После готового APK обновляется локальная apk-releases/latest.apk и серверный Android download. /app выдаёт согласованную кнопку скачивания. Только после проверки live ссылки/документов/одноразового состояния — явно запрошенная владельцем рассылка всем доступным пользователям Telegram.

## Проверки

Backend: version/hash validation, independent records, ownership, idempotency/repeat, existing unaccepted accounts, new auth/profile status, stale/false payload rejection. Frontend: unchecked defaults, independent selection, safe documents, submit/retry/error, repeat login no popup, account switch, old cached profile, offline accepted/unaccepted, preserved active session. Migration runner повторно, packaging docs, Ruff/TS/lint/unit/browser shared/native checks.

Проверка 320/393/1440px, светлая/тёмная тема, dialog/focus/Escape/BackButton. Pending sync при обязательном подтверждении не теряется. Существующие числовые замеры/дневник не меняются этим этапом.

## Нормативные ориентиры и границы

152-ФЗ: ст.9 (отдельное согласие, доказательство, отзыв); ст.10 (специальные категории и письменная форма); ст.18.1/19 (политика/организационные меры/защита), ст.21/22 (прекращение/уведомление). ГК РФ ст.435/438 (оферта/акцепт). Тексты не утверждают, что регистрация в Роскомнадзоре, договоры обработки или отдельное письменное согласие уже оформлены. Эти факты проверяются владельцем отдельно; checkbox не заменяет организационные обязанности.
