# UX-ревью со стороны пользователя

**Дата:** 2026-08-05  
**Контекст:** проход по Mini App как у нового/вернувшегося пользователя + сверка с текущим UI/кодом после фич: уведомления (вода/калории/догон), расписание добавок, сканер штрихкода, правка подходов.  
**Среда проверки:** локальный фронт `http://127.0.0.1:5173`, API `:8001`, ngrok-туннель поднят.  
**Ограничение теста:** в обычном браузере без Telegram WebApp **нет полноценной авторизации** («Откройте Mini App в Telegram…»). Поэтому часть сценариев (логирование сета, сохранение профиля, реальный OFF/скан с API) оценена по UI + коду + недавним ручным фиксам; полный device-QA — только внутри Telegram.

---

## 1. Краткий вердикт

Продукт уже **не выглядит как сырой MVP**: есть понятная навигация (5 вкладок), дневник питания со сканером, привычки, прогресс, профиль с программой/добавками/уведомлениями, активная тренировка с быстрым логом.

Главные UX-разрывы сейчас не в «красоте», а в:

1. **Первом успехе** — без выбранной программы главная «пустая» и не ведёт за руку.  
2. **Плотности экранов** — Профиль / Питание / Активная тренировка перегружены.  
3. **Обратной связи после действий** — часть действий «проглатывается» или требует лишних шагов.  
4. **Зависимости от Telegram + онлайна** — вне TG и офлайн-сценарии слабые/неочевидные.

**Оценка зрелости UX:** ~7/10 для Telegram fitness mini-app.  
До «ежедневного привычного инструмента» не хватает полировки empty-states, подтверждений и упрощения 2–3 ключевых потоков.

---

## 2. Карта пользовательских потоков

| Поток | Что видит пользователь | Оценка |
|-------|------------------------|--------|
| Вход | Только через Telegram; email отключён | Ожидаемо для TG, плохо для web-preview/QA |
| Онбординг → первая тренировка | Есть авто-программа (по коду), но без auth не проверить end-to-end | Критичный путь — держать под E2E в TG |
| Главная «сегодня» | Streak, привычки, CTA программы | Хороший каркас, слабый empty-state |
| Тренировка | Хаб → программы/каталог → active workout | Сильный core, сложный UI сессии |
| Питание | Поиск, каталог, сканер, граммы, приёмы | Сильный рост; поток скана уже лучше |
| Прогресс | Streak, бейджи, питание, объём | Информативно, много «нулей» у новичка |
| Профиль | 4 вкладки: тело/программа/добавки/уведомления | Мощно, но тяжело |
| Ещё | Профиль + AI | Чисто и правильно |

## 3. Что уже хорошо (оставить / усилить)

### 3.1 Навигация
- Нижнее меню из 5 пунктов: **Главная · Тренировки · Питание · Прогресс · Ещё** — правильный каркас.
- AI и профиль убраны «в Ещё» — не засоряют таббар.
- Зоны тапа ≥44px на навигации — плюс для мобильного TG.

### 3.2 Питание (после последних правок)
- Сканер **не форсит** запись: выбирает продукт → предлагает граммы → пользователь жмёт «Добавить».
- Быстрые чипы **50/100/150/200/250 г** — закрывают кейс «на упаковке 250, съел 100».
- «Как вчера», избранное/недавние, override БЖУ — сильный набор для реального дневника.
- Цель калорий + Б/Ж/У и ссылка в профиль — понятная связка.

### 3.3 Тренировка
- Быстрый лог: «Готово» без модалки, «Как прошлый», «Изменить» правит **тот же** подход (не плодит новый) — важный UX-win.
- Rest timer, AI-замена, media — уровень выше типичного трекера.

### 3.4 Уведомления / добавки
- Вода: литраж, интервал, окно времени.
- Калории: слоты + недобор/перебор.
- Догон без спама (digest) — правильное продуктовое решение после ночного рестарта.
- Добавки: несколько времён + **каждый день / день тренировки / день без тренировки** — закрывает реальные схемы (протеин/креатин/бета-аланин).
- Пользовательские тексты вместо Redis/arq — правильно.

### 3.5 Прогресс и мотивация
- Streak, бейджи, силовые тренды, сводка питания — хороший «mirror» прогресса.
- Пустые состояния хотя бы объясняют, *когда* появятся данные.

## 4. Замечания по экранам

### 4.1 Главная
**Как есть**
- Блок «Сегодня» + streak + синхронизация + привычки + кнопки программ.
- Без программы: «Выберите готовую программу…» + «Выбрать программу».

**Комментарии**
- Для новичка слишком много вторичного (streak 0, sync 0, привычки) **до** главного действия.
- «Синхронизация: 0 / онлайн» — технический статус, не пользовательская ценность.
- Нет явного «что делать прямо сейчас за 10 секунд», если программа уже есть vs нет — визуально похожие состояния.

**Предложения**
1. **Hero-CTA один:**  
   - нет программы → «Выбрать программу на 10 минут»;  
   - есть программа → «Начать тренировку · День N»;  
   - есть активная сессия → «Продолжить тренировку».
2. Привычки свернуть в одну строку «Вода 0/2500 · Вес · Сон» с expand.
3. Убрать/спрятать «Синхронизация» в long-press/Ещё/отладку; обычному юзеру — только «Сохранено» / «Ждёт сети».
4. После +250/+500 мл воды — короткий toast «750 / 2500 мл» (сейчас легко не заметить эффект).

### 4.2 Тренировки (хаб)
**Как есть**
- Две крупные карточки: Программы / Каталог. Чисто.

**Комментарии**
- Хороший «перевалочный» экран, но почти пустой по ценности: нет «продолжить», «следующий день программы», «последняя тренировка».

**Предложения**
1. Добавить сверху карточку **контекста**: активная программа, день, кнопка старта.
2. Третий пункт: «История / последние 3 тренировки» (deep link в прогресс).

### 4.3 Программы
**Как есть**
- Фильтры пол/тип/уровень, empty «Нет программ…».

**Комментарии**
- Уровни в UI как `beginner/intermediate/advanced` (EN) — выбивается из русского интерфейса.
- Без auth empty-state смешивает «нет данных» и «нужен вход».
- Много фильтров сразу — когнитивная нагрузка до первого выбора.

**Предложения**
1. Локализовать уровни: Новичок / Средний / Продвинутый.
2. По умолчанию: **рекомендованные 3** + кнопка «Все фильтры».
3. На карточке: длительность, дней/нед, дом/зал, бейдж ограничений — одним взглядом.
4. После «Выбрать» — сразу «Начать день 1» (не только сохранить в профиль).

### 4.4 Активная тренировка
**Как есть**
- Богатый экран: медиа, подходы, rest, AI, finish.

**Комментарии**
- Экран очень плотный (много кнопок/состояний) — в зале с потом/одной рукой легко промахнуться.
- «Изменить» vs «Добавить +» — логика стала верной, но подписи можно яснее.
- Завершение тренировки (MainButton / панель) конкурирует с логом сетов.
- Нет явного «пропустить упражнение» / «сделал частично» на первом уровне.

**Предложения**
1. **Режим зала (simple mode):** крупно только текущий подход + Готово + таймер; остальное в «Ещё».
2. Подпись «Изменить» → «Править этот подход»; «Добавить +» оставить.
3. После «Готово» — автофокус/подсветка следующего подхода + лёгкая вибрация (Haptic).
4. Свайп/кнопка «Пропустить упражнение» с confirm.
5. На finish: 1 вопрос RPE + опциональная заметка, без лишних полей.

### 4.5 Питание
**Как есть**
- Сканер, приёмы, поиск, каталог, граммы, чипы, список приёмов.

**Комментарии**
- Каталог по умолчанию **открыт** («Скрыть каталог») — экран длинный, кнопка «Добавить» уезжает вниз.
- Без auth: «Нет продуктов» + «Нужна авторизация» — двойной негативный empty.
- Нельзя быстро **удалить/править** запись в приёме (если нет — критичный gap; если есть глубоко — не discoverable).
- Сканер зависит от камеры/BarcodeDetector; fallback ручным EAN есть — хорошо, но пользователь может не понять, почему «не пикает».
- Дата только «сегодня» в UI заголовка — нельзя листать вчера/позавчера без обходных путей.

**Предложения**
1. Каталог **свёрнут по умолчанию**; после выбора продукта — скролл к блоку «Граммы + Добавить».
2. После скана: sticky-бар «ТЕОС · [100 г] · Добавить в Завтрак».
3. В списке приёма: свайп/кнопки изменить граммы и удалить.
4. Переключатель даты ← сегодня →.
5. Если OFF не нашёл товар — мастер «создать продукт» с уже подставленным barcode.
6. Долгое нажатие на чип граммов = custom (например 80 г) через stepper.

### 4.6 Прогресс
**Как есть**
- Streak, завершено, привычки, достижения 0/6, силовые тренды, питание, объём 14 дней.

**Комментарии**
- У новичка стена нулей + длинные объяснения (Epley, кг·повт.) — выглядит «сложно и пусто».
- «Источник: сервер» — снова тех.язык.
- Дублируется блок привычек с главной.

**Предложения**
1. Для 0 тренировок — **один** empty: «Закройте первую тренировку — здесь появится серия и графики» + CTA.
2. Бейджи оставить 2–3 ближайших, остальные «Показать все».
3. Привычки на прогрессе — только недельный strip, без полного чекина (чекин на главной).
4. Подписи проще: «Ориентир максимума» вместо «1ПМ (Epley)» в первом уровне; формула — в «i».

### 4.7 Профиль
**Как есть**
- 4 таба, очень большой экран (тело, программа, добавки, уведомления).

**Комментарии**
- Это «настройки всего продукта» в одном месте — мощно для power-user, тяжело для новичка.
- Добавки: расписание гибкое (every/workout/rest) — отлично; но UI строк расписания может быть громоздким.
- Уведомления: много тумблеров; «Проверить напоминания сейчас» полезно, но рядом с user-copy всё ещё «сервисная» кнопка.
- Риск: пользователь настроит добавки, но забудет включить «Приём добавок» на вкладке Уведомления — два места правды.

**Предложения**
1. Мастер «Быстрый профиль» (пол/вес/цель/дни) vs «Расширенные».
2. Связка добавки↔уведомления: на вкладке Добавки чип «Напоминания: вкл» с deep-link.
3. Для уведомлений — пресеты: «Утро», «Тренировочный день», «Минимум».
4. «Проверить напоминания» показывать только если уже что-то включено; результат человеческим языком: «Отправлено 1: вода».

### 4.8 AI-тренер
**Как есть**
- Отдельный чат в «Ещё» + contextual assist в тренировке.

**Комментарии**
- Ценность AI выше **в контексте** (замена упражнения), чем как отдельный чат «в вакууме».
- Новичок может не найти AI.

**Предложения**
1. На главной/после тренировки 1 soft-entry: «Спросить тренера про сегодня».
2. В чате — chips: «Замена при боли в колене», «Разбор недели», «Что есть после тренировки».
3. Не обещать медицину; короткие ответы + кнопка «Применить» (замена/рецепт действий в приложении).

### 4.9 Онбординг / доступ
**Комментарии**
- Жёсткая привязка к Telegram — ок для продукта, плохо для поддержки/превью.
- Сообщение «Вход по email временно отключён» звучит как поломка, не как политика.

**Предложения**
1. Текст: «Войдите через кнопку Mini App в боте» + deep-link/инструкция.
2. Для dev/staging — явный demo-login (не в prod).
3. После онбординга — checklist из 3 шагов: программа ✓ · первая тренировка · первый приём пищи.

## 5. Сквозные UX-проблемы

| # | Проблема | Почему важно | Приоритет |
|---|----------|--------------|-----------|
| 1 | Empty-states не ведут к действию | Новичок «залипает» на нулях | P0 |
| 2 | Тех.копирайт (sync, server, beginner, Epley) | Снижает доверие/ясность | P0 |
| 3 | Перегрузка Профиля и ActiveWorkout | Ошибки в зале / отказ настраивать | P0–P1 |
| 4 | Мало подтверждений успеха (toast) | Кажется, что «не нажалось» | P0 |
| 5 | Нет удобного edit/delete в дневнике питания* | Страх ошибиться граммами | P0 |
| 6 | Дата питания = только сегодня | Нельзя добить вчерашний день | P1 |
| 7 | Офлайн-история неочевидна | TG/метро/зал = дыры в сети | P1 |
| 8 | Дубли привычек Главная/Прогресс | Шум | P2 |
| 9 | Сканер: различия клиентов TG/WebView | «У меня не сканирует» | P1 |
| 10 | Два рубильника для добавок (стек + alerts) | «Почему бот молчит?» | P1 |

\*Проверить на device: если edit/delete логов уже есть — сделать заметнее; если нет — добавить.

## 6. Предложения по приоритетам

### P0 — сделать в ближайший цикл
1. **Sticky-confirm после скана/выбора продукта** (продукт + граммы + приём + Добавить).  
2. **Edit/delete** записей дневника питания.  
3. **Единый success toast** на воду, питание, сет, сохранение профиля.  
4. **Главная: один primary CTA** по состоянию (нет программы / старт / продолжить).  
5. **Локализация** `beginner/intermediate/advanced` и убрать тех.строки из user-facing UI.  
6. **Связка добавки → уведомления** (статус «напоминания вкл/выкл»).

### P1 — усиление ежедневного использования
1. Листание дней в питании.  
2. Simple mode активной тренировки.  
3. Хаб «Тренировки» с карточкой текущей программы.  
4. Пресеты уведомлений.  
5. Offline banner: «Сохраним, когда появится сеть» + очередь понятным языком.  
6. Сканер: экран-подсказка «держите ровно / или введите код».  
7. Прогресс: empty-first для новичков.

### P2 — рост удержания
1. Недельный обзор «что получилось» (тренировки + калории + вода).  
2. Умные подсказки: «вчера недобор белка», «3 дня без тренировки — лёгкий старт».  
3. Шаблоны приёмов пищи («завтрак 400 ккал»).  
4. Быстрый повтор последнего отсканированного товара.  
5. A11y: focus order, contrast, reduce motion для таймера.

### P3 — платформа / качество
1. Device E2E в Telegram: онбординг → сет → finish → скан → лог.  
2. Метрики: time-to-first-set, time-to-first-meal, barcode success rate, notification open rate.  
3. Demo-auth для web QA.  
4. Скриншот-тесты ключевых empty/full состояний.

## 8. Сценарии для ручного device-QA (чеклист)

Пройти **внутри Telegram**, не в Chrome:

- [ ] Онбординг → главная с программой и CTA старта  
- [ ] Старт тренировки → 1 подход «Готово» без модалки → «Изменить» тот же подход → finish  
- [ ] Питание: скан → граммы 250→100 → Добавить → запись в нужном приёме  
- [ ] Питание: правка/удаление записи  
- [ ] Вода +250 на главной → цель/остаток  
- [ ] Добавка: время 07:00 «без тренировки» + 05:00 «тренировка» → сохранить → тестовое уведомление  
- [ ] Выключить worker на 5 мин → включить → один digest, без пачки дублей  
- [ ] Профиль: ограничения no_knee → старт «чужой» программы → warning  
- [ ] Офлайн на 1 сет → онлайн → sync без потери  

---

## 9. Итог

**Сильные стороны:** навигация, тренировочный core, питание со сканером (после confirm-grams), гибкие напоминания добавок, догон уведомлений без спама.

**Главный фокус дальше:**  
> «От открытия до первого полезного действия — меньше 30 секунд, и каждое действие должно быть очевидно успешным.»

Если брать один пакет работ на спринт:

1. Confirm-grams sticky + edit/delete nutrition  
2. Home primary CTA + toasts  
3. Упрощение copy (без tech) + связка supplements/alerts  

Это даст максимальный прирост «ежедневности» без новых больших подсистем.
