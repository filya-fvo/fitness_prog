# Визуальная система Fitness Mini App

## Базовые принципы

- Доступны светлая и тёмная темы. По умолчанию приложение следует теме Telegram
  или устройства; явный выбор пользователя имеет приоритет. Обе палитры сохраняют мягкие
  голубые и фиолетовые акценты. Яркий градиент используется только для
  главного действия и активного пункта навигации, а не для каждой карточки.
- Мобильная компоновка сохраняется до `md`; на desktop рабочая область ограничена `max-w-5xl`, содержательные формы — `max-w-4xl`.
- Основное действие экрана использует `bg-tg-button`; вторичные действия — `bg-tg-secondary` или текстовую ссылку.
- Минимальная высота сенсорного действия — 44 px.
- Значимый пользовательский текст не должен быть меньше 12 px.
- Состояние выбранного элемента обозначается не только цветом: используются фон, насыщенность, подпись или символ.
- Знак в корневом заголовке — только буква `F` без гантелей, звёзд и мелких
  деталей: при размере 44 px он должен читаться с первого взгляда.

## Tokens

Tokens объявлены в `frontend/src/index.css`:

- spacing: `--space-page`, `--space-section`;
- radii: `--radius-card`, `--radius-control`;
- surfaces: `--surface-primary`, `--surface-secondary`, `--surface-inset`;
- border: `--border-subtle`;
- semantic colors: `--color-success`, `--color-warning`, `--color-danger`.
- brand colors: `--app-bg`, `--app-bg-deep`, `--app-surface`, `--app-text`,
  `--app-hint`, `--app-accent`, `--app-violet`, `--app-button`.

Тема задаётся атрибутом `data-theme="light|dark"` и классом `dark` на `<html>`.
Новые цвета должны идти через токены, а не через жёстко заданный тёмный hex. Исключение —
камера, видео и специальные полноэкранные overlay, где чёрный фон нужен для читаемости.
Нативные пункты `select option` явно получают фон `--app-surface` и текст `--app-text`,
чтобы системное раскрывающееся меню не давало светлый текст на белом фоне.

Фон страницы состоит из адаптивного для выбранной темы градиента и двух очень слабых цветовых пятен.
Не добавляйте полноэкранные фотографии под формы: они снижают читаемость и
увеличивают первую загрузку. Иллюстрации допустимы как локальный акцент в empty
state или onboarding, если не конкурируют с основным действием.

Для новых экранов предпочтительны классы `surface-card`, `surface-inset`, `state-success`, `state-warning`, `state-danger` и Telegram theme variables. Не задавайте отдельные серые фоны и радиусы без необходимости.

## Упражнения и графики

- В длинных списках упражнений используется `ExerciseThumbnail`: явный
  `thumbnail_url`, либо сгенерированный PNG первого кадра локальной GIF, либо
  нейтральная пиктограмма. Не запускайте анимированные GIF одновременно во всех
  строках каталога.
- Полная анимация и атрибуция источника остаются в `ExerciseMediaPlayer`.
- Во время тренировки показывается компактный дневник последнего выполнения.
  Большой график упражнения открывается отдельным modal/bottom sheet и не
  раздвигает форму подходов.
- График обязан иметь видимые крайние/последние значения, единицы измерения,
  период и понятное пустое состояние. `title`/hover — дополнение, не единственный
  способ прочитать значение на сенсорном экране.
- Отсутствие записи визуально отличается от нулевого значения. В частности,
  пустой день питания нельзя изображать как подтверждённый дефицит.
- Цвета графиков: голубой — основная серия, фиолетовый — дополнительный акцент,
  зелёный — положительное изменение, оранжевый — превышение цели. Красный не
  применяется для обычного колебания показателей.
- Подписи осей и ключевые значения размещаются в HTML с фактическим размером
  от 12 px: текст внутри масштабируемого SVG не обеспечивает этот минимум.
  Для плотных графиков показываются крайние и несколько промежуточных дат.
  `ChartDataTable` раскрывает значения всех показанных точек, включая нули
  и пропуски; таблицу можно прокрутить с клавиатуры. Tooltip остаётся дополнением.
- При системном снижении движения GIF начинается с неподвижного кадра.
  Пользователь может явно запустить и остановить её. Статичные фото и миниатюры
  не получают кнопок анимации. CSS-анимации, переходы и плавная прокрутка
  также учитывают эту настройку через общие правила и `utils/motion.ts`.

Корневые контейнеры используют `100dvh` с fallback `100vh`, `viewport-fit=cover` и safe-area отступы. На iPhone нельзя отключать масштабирование через viewport: вместо этого поля остаются не меньше 16 px, а системное увеличение текста фиксируется через `text-size-adjust: 100%`.

## Состояния и доступность

- Все интерактивные элементы должны иметь заметный `focus-visible`.
- Кнопки без видимого текста получают `aria-label`.
- Модальные окна используют `useModalAccessibility`: Escape, focus trap, возврат фокуса и блокировка фоновой прокрутки.
- Технические ошибки преобразуются через `toUserMessage`; подробности остаются в логах/Sentry.
- Для загрузки, меняющей структуру страницы, используется `PageSkeleton`.
- На мобильных все видимые `input`, `select` и `textarea` имеют шрифт не меньше
  16 px, чтобы iOS не увеличивал страницу при фокусе.
- Контраст текста и действий должен проходить WCAG AA; проверка публичных экранов
  закреплена в `frontend/e2e/accessibility.spec.ts`.
- До `lg` используется нижняя навигация с safe-area, начиная с `lg` — верхняя;
  контент получает соответствующий отступ и не должен оставлять мобильную пустоту.
- У каждого поля есть связанное имя. Ошибка проверки связана с полем через
  `aria-describedby`, обозначается `aria-invalid`; после отправки фокус
  переходит к первой ошибке. Исправление значения снимает устаревшую ошибку.
- Простые переключатели групп данных используют обычные кнопки с
  `aria-pressed`. Семантика `tablist/tab` допустима только вместе с панелями
  и полноценным клавиатурным управлением вкладками.
- Длинный ИИ-разбор сначала свёрнут; явная кнопка раскрывает полный текст.
  Новый ответ снова показывается кратко.
- `useRecoverableDraft` сохраняет только явно выбранные поля длительных форм,
  отдельно для аккаунта и контекста (дата замера, объект рассылки, раздел профиля).
  Сохранение на сервер и отмена очищают соответствующий черновик; фоновое
  обновление не заменяет ввод. Пароли, OTP и токены в такие черновики не попадают.
  При недоступном хранилище форма сообщает об этом: сохранение черновика между
  переходами в этом режиме не гарантируется.

## Навигация назад

- Пять корневых вкладок: `/` — Главная, `/train` — Упражнения, `/progress` —
  Дневник, `/help-center` — Помощь, `/profile` — Профиль. Они и onboarding
  не показывают стрелку назад; `/more` перенаправляет в Профиль.
- Вложенные страницы используют общий `components/layout/Header.tsx`: сначала
  возврат по фактической истории React Router, а при прямой ссылке — в раздел-
  владелец по `lib/appNavigation.ts`: программы, каталог и активная тренировка
  → Упражнения; замеры → Дневник; настройки, уведомления, друзья и приглашения
  → Профиль; ИИ, поддержка и справка → Помощь. Админские дочерние экраны → админка.
- Header управляет внутренней навигацией. Telegram `BackButton` скрыт:
  Android сохраняет системный выход, а `useTelegramExitGesture` в Shell
  обслуживает узкий жест от края на iOS. Не регистрируйте собственный Telegram
  BackButton для нового экрана. Защита черновиков не должна перехватывать выход
  из Telegram.
- Кнопка имеет доступное имя «Вернуться назад» и область нажатия не меньше 44 px.
