# Инструкция администратора: замена провайдера или AI-модели

Эта инструкция описывает штатную замену модели AI-тренера без изменения кода и пользовательских данных. Backend поддерживает Groq как основной провайдер и OpenAI как отключённый резерв.

## Кратко

Текущая локальная конфигурация использует Groq Chat Completions API:

```env
AI_PROVIDER=groq
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=qwen/qwen3.6-27b
LLM_FALLBACK_MODELS=openai/gpt-oss-120b,llama-3.3-70b-versatile,openai/gpt-oss-20b,llama-3.1-8b-instant
```

Ключ Groq задаётся отдельно как `LLM_API_KEY`. OpenAI-переменные сохраняются для возможного переключения, но при `AI_PROVIDER=groq` не используются.

Обычная замена модели или провайдера не требует миграции БД. Не удаляйте AI-историю и `users.openai_conversation_id`: Groq получает последние сообщения из локальной БД, а сохранённый OpenAI Conversation остаётся доступен на случай обратного переключения.

## 1. Когда менять модель

Замену следует запланировать, если:

- провайдер объявил дату отключения текущей модели;
- API возвращает `model_not_found`, ошибку доступа или сообщение об отключённой модели;
- другая модель стала заметно дешевле или лучше отвечает на русском языке;
- текущая модель перестала укладываться в доступные лимиты провайдера.

Не ждите даты отключения. Проверяйте модель в документации активного провайдера:

- [Supported Models — Groq](https://console.groq.com/docs/models)
- [Models — OpenAI API](https://developers.openai.com/api/docs/models)
- [Deprecations — OpenAI API](https://developers.openai.com/api/docs/deprecations)

Название нужно копировать именно из API-документации или ответа `GET /models`, а не из маркетингового интерфейса. Например, корректный Groq ID — `qwen/qwen3.6-27b`.

## 2. Как выбрать замену

Новая модель должна:

1. Быть доступна для используемого аккаунта и ключа.
2. Для Groq поддерживать Chat Completions (`POST /chat/completions`), а для OpenAI — Responses API (`POST /responses`).
3. Принимать системные и пользовательские текстовые инструкции.
4. Позволять ответ до 600 токенов.
5. Подходить по цене, лимитам запросов/токенов и качеству ответов на русском языке.

Есть два варианта идентификатора:

- alias, например `gpt-5-nano`: OpenAI может обновлять реализацию за тем же именем;
- snapshot с датой: поведение стабильнее, но администратор обязан вручную перейти на следующий snapshot до его отключения.

Для этого приложения практичнее стабильный ID недорогой мультиязычной модели. Snapshot выбирайте только тогда, когда воспроизводимость ответов важнее ручной миграции.

## 3. Замена локально

1. Откройте `C:\fitness_prog\backend\.env`.
2. Для другой модели Groq сохраните прежнее значение комментарием и укажите основной ID и каскад без повторов:

```env
# Предыдущая модель; заменена 2026-08-11 из-за <причина>
# LLM_MODEL=qwen/qwen3.6-27b
AI_PROVIDER=groq
LLM_MODEL=<точный-api-id-новой-модели>
LLM_FALLBACK_MODELS=<резерв-1>,<резерв-2>,<резерв-3>
```

3. Не меняйте `LLM_API_KEY` и `LLM_BASE_URL`, если остаётесь на Groq.
4. Для возврата на OpenAI задайте `AI_PROVIDER=openai`, проверьте `OPENAI_API_KEY`, `OPENAI_BASE_URL` и `OPENAI_MODEL`.
5. Перезапустите backend, потому что `.env` читается при старте процесса:

```powershell
C:\fitness_prog\scripts\dev.cmd restart-backend
```

Не добавляйте кавычки и пробелы вокруг идентификатора модели. Не помещайте API-ключ во frontend, документацию, Git или сообщения об ошибках.

## 4. Замена в production

### Render

1. Откройте Render Dashboard → сервис `fitness-api` → Environment.
2. Для Groq проверьте `AI_PROVIDER`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` и `LLM_FALLBACK_MODELS`.
3. Сохраните переменную и выполните redeploy/restart сервиса.
4. Обновите такое же значение в корневом `render.yaml`, чтобы следующий Blueprint deploy не вернул старую модель.

`LLM_API_KEY` и необязательный `OPENAI_API_KEY` должны оставаться секретными переменными Render. В worker модель сейчас не используется: AI-запросы выполняет `fitness-api`.

### VPS, Docker или другой хостинг

Измените `AI_PROVIDER` и соответствующую переменную модели (`LLM_MODEL` для Groq или `OPENAI_MODEL` для OpenAI) именно у backend-сервиса, затем пересоздайте контейнер или перезапустите процесс API.

## 5. Проверка перед выпуском

Сначала прогоните профильные backend-тесты:

```powershell
cd C:\fitness_prog\backend
.\.venv\Scripts\python.exe -m pytest tests\test_ai_engine_llm.py tests\test_llm_prompts.py
.\.venv\Scripts\python.exe -m ruff check app tests
```

После перезапуска проверьте health endpoint:

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health
```

Затем выполните один реальный запрос в Mini App:

1. Спросите AI-тренера о текущей программе или последней тренировке.
2. Убедитесь, что ответ основан на фактических данных пользователя.
3. Проверьте подпись «Ответ OpenAI». Подпись «Локальный резервный ответ» означает, что внешний вызов не удался.
4. Закройте и снова откройте чат: история текущих суток должна сохраниться.
5. Проверьте backend-логи на `groq_response_failed`, `openai_response_failed` и `unsupported_ai_provider`.

После проверки внесите запись в `docs/CHANGELOG.md`:

```text
- AI_PROVIDER: <старый> → <новый>; модель: <старая> → <новая>.
- Причина: <депрекация / цена / качество / лимиты>.
- Проверено: <дата>, профильные тесты и реальный запрос — успешно.
```

## 6. Откат

Если новая модель отвечает с ошибкой или заметно ухудшила качество:

1. Верните прежние `AI_PROVIDER` и ID модели.
2. Перезапустите/redeploy backend.
3. Повторите health check и реальный запрос.

Не очищайте таблицы пользователей, AI-истории и `openai_conversation_id`. Для отката модели это не требуется.

## 7. Типовые ошибки

| Симптом | Что проверить |
|---|---|
| `401 Unauthorized` | Соответствие ключа провайдеру: `LLM_API_KEY` для Groq или `OPENAI_API_KEY` для OpenAI. |
| `404` или `model_not_found` | Точный API ID, доступность модели проекту, дату отключения на странице Deprecations. |
| `429` + `insufficient_quota` / `credit_balance_exhausted` | На API-балансе нет средств. Добавьте credits в OpenAI Platform → Billing и проверьте, что ключ относится к нужному проекту/организации. |
| `429` + `rate_limit_exceeded` | Исчерпан лимит модели. Для Groq backend временно исключает её и пробует следующий ID из `LLM_FALLBACK_MODELS`. Это не то же самое, что внутренний лимит приложения `AI_DAILY_LIMIT=10`. |
| `400` с unsupported parameter | Поддерживает ли модель Responses API, `instructions` и `max_output_tokens`. |
| В интерфейсе «Локальный резервный ответ» | Backend-логи, ключ, ID модели, сеть и доступность OpenAI API. |
| После изменения продолжает использоваться старая модель | Перезапущен ли backend и изменена ли переменная именно у `fitness-api`. |

## 8. Когда нужна доработка кода

Одной переменной модели недостаточно, если новая модель:

- не поддерживает Responses API;
- требует другой endpoint или обязательные параметры;
- не принимает текущий формат `instructions`/`input`;
- возвращает текст в несовместимом формате;
- требует другой OpenAI-совместимый провайдер и базовый URL.

В таком случае до развёртывания нужно изменить и протестировать:

- `backend/app/services/ai_engine.py` — запрос и разбор ответа;
- `backend/app/core/config.py` — конфигурацию, если появились новые параметры;
- `backend/tests/test_ai_engine_llm.py` — контракт с API;
- `backend/.env.example`, `backend/.env.production.example` и `render.yaml` — примеры окружения/deploy.

Если меняется только поддерживаемый model ID в пределах текущего API провайдера, исходный код менять не нужно.

## 9. GitHub Models использовать нельзя

GitHub полностью закрыл GitHub Models 30 июля 2026 года. Playground, каталог, inference API и BYOK больше недоступны. Не добавляйте `GITHUB_MODELS_TOKEN` и не включайте старый endpoint `models.github.ai` в каскад.

Актуальное уведомление: [GitHub Models has been retired](https://docs.github.com/en/enterprise-cloud@latest/github-models).

## 10. Как работает каскад Groq

Backend пробует модели в порядке `LLM_MODEL`, затем `LLM_FALLBACK_MODELS`. Переход выполняется при `429`, блокировке/отсутствии конкретной модели (`403`/`404`) или серверной ошибке Groq (`5xx`). Ошибки ключа и некорректного тела запроса не запускают перебор моделей.

После `429` модель помещается во временный cooldown на значение заголовка `retry-after`; следующие запросы сразу идут к доступной модели. Все модели используют один Groq-ключ и лимиты одной организации. Не создавайте дополнительные аккаунты или организации для обхода лимитов.

Текущая цепочка:

1. `qwen/qwen3.6-27b`
2. `openai/gpt-oss-120b`
3. `llama-3.3-70b-versatile`
4. `openai/gpt-oss-20b`
5. `llama-3.1-8b-instant`

Проверяйте точные лимиты организации в Groq Console: ограничение по токенам может закончиться раньше ограничения по числу запросов. Логи переключения: `groq_model_skipped` и `groq_fallback_succeeded`.
